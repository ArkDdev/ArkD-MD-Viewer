# Итерация 2.5 — текст модала + чистка зависимостей

## Что нужно сделать

1. Распакуй архив поверх проекта. Два файла:
   - `src/components/chrome/ConflictModal.tsx`
   - `package.json`

2. **Запусти `npm install`** — это удалит `katex` из `node_modules` (он был в зависимостях, но не использовался).

3. Hot-reload подхватит изменения в модале автоматически.

## Что изменилось

### Модал

- **Заголовок:** "Обновление файла" (было: "Файл изменён извне")
- **Описание:** теперь объясняет последствия — "Если загрузить обновлённую версию, ваши текущие изменения в редакторе будут потеряны"
- **Кнопка:** "Загрузить обновлённый файл" (было: "Загрузить с диска")

Заметь, что описание теперь корректно работает и для **чистого буфера в edit-режиме** — раньше я писал "У вас есть несохранённые изменения", что было неточно (в режиме split modal показывается даже когда буфер чистый).

### Удалена зависимость KaTeX

В `package.json` убран `"katex": "^0.16.11"` — он лежал там с самого начала "на будущее", но мы решили математику не поддерживать.

**Освобождается ~1.2 МБ в `node_modules`** (это сам KaTeX + его зависимости в dev-окружении). На production-bundle это влияния не оказывает (он туда не попадал, потому что нигде не импортировался), но при `npm install` он зря качался и занимал место.

После `npm install`:
- npm удалит katex из node_modules
- `package-lock.json` обновится

## Что я помечу для будущего

Mermaid и KaTeX окончательно вычеркнуты из плана. Если когда-нибудь захочешь их вернуть — это потребует осознанного решения. По размеру:

- **KaTeX** возвращать стоит **только** если планируется регулярная работа с формулами. Иначе lazy-load по факту встречи `$...$` в документе будет лучшим компромиссом.
- **Mermaid** я бы вообще не возвращал. Если когда-то понадобится визуализировать архитектуру, есть альтернативы поменьше: `excalidraw-svg-renderer` (~50 КБ), кастомные ASCII-диаграммы, или просто скриншоты схем из других инструментов.

## Размер бандла после этой итерации

Если интересно, текущая прикидка для production-сборки (`npm run tauri:build`):

- Финальный `.exe` установщик: **~6-8 МБ** (Tauri base + наш Rust код + frontend)
- Из них frontend JS: **~600-800 КБ** (gzipped: ~200 КБ)
- Rust backend бинарник: **~5-6 МБ** (release, с LTO)

Это очень компактно для приложения с такой функциональностью. Для сравнения: Obsidian (~150 МБ), Typora (~70 МБ), Marktext (~120 МБ).
